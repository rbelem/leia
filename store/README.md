# Leia store submission kit

Everything needed to publish Leia on Chrome Web Store, Firefox Add-ons (AMO), and Microsoft Edge Add-ons. Text lives in `copy/`, art in `icons/` and `promo/`, live captures in `screenshots/`, packages in `pkg/`. One command gates the whole kit: `node scripts/store-check.mjs`.

Tag a release (`vX.Y.Z`) and `.github/workflows/release.yml` gates, packages reproducibly, and publishes every store whose secrets are configured (dry-running the rest). Secrets, failure playbook, and local reproduction: `publishing/README.md`.

## Layout

- `copy/copy.json` — single source for name, short description, AMO summary, tags, categories. The checker validates the lengths and that `src/manifest.json` agrees.
- `copy/long-description.md` — the listing description all three stores get (written plain-text on purpose; CWS and Edge do not render markdown).
- `copy/chrome.md`, `copy/firefox.md`, `copy/edge.md` — per-store runbooks: field mapping, asset slots, privacy answers, review notes, steps. Sources for every requirement are linked at the top of each.
- `icons/leia-icon.svg` — the promoted identity (the marching-highlight glyph). `icons/concepts/` keeps the two runner-up concepts. `leia-*.png` are the exports; `--install` copies the manifest sizes onto `src/icons/icon*.png`.
- `promo/` — CWS/Edge small tile (440x280, required on CWS) and marquee (1400x560, optional/featuring; Edge's large tile takes the same file).
- `screenshots/` — captured from the live extension (see `scripts/capture-screenshots.mjs` header for why a mirror pass exists: Chromium's CDP capture skips CSS Custom Highlight paint).
- `privacy-policy.md` — hosting-ready policy. Host it publicly and paste the URL into every dashboard.
- `pkg/` — versioned packages. `leia-chrome-<v>.zip` and `leia-firefox-<v>.zip` are regenerated by the commands in the runbooks; the zips themselves are not committed.

## Regenerating art

```
node scripts/render-store-art.mjs --install   # render every PNG + swap src/icons
node scripts/render-store-art.mjs --check     # dimension gate only
```

Chromium renders; `$CHROMIUM` or the devbox profile binary is used. No image library is involved: the script asserts pixel dimensions from each PNG's IHDR bytes.

## Regenerating screenshots

```
npm run build -- --dev
LEIA_STATE_DIR=/tmp/opencode/leia-shots node cli/index.js up --chrome-bin <chromium>
LEIA_STATE_DIR=/tmp/opencode/leia-shots node cli/index.js open-fixture
LEIA_STATE_DIR=/tmp/opencode/leia-shots node scripts/capture-screenshots.mjs
# any article: node scripts/capture-screenshots.mjs <url> <name>.png
```

The engine is pinned to `kitten-local` because hosts without system TTS have no Web Speech voices. `leia up` can fail extension-id discovery on a cold first start; rerun it once.

## Before every submission

1. `npm run typecheck && npm test`
2. `npm run build`
3. `node scripts/store-check.mjs`
4. Re-zip per the runbook (`store/copy/<store>.md`), then upload.

## Open items the store dashboards will ask about

- **Name go/no-go (human call).** The name "Leia" predates this kit and PRODUCT.md binds it internally, but no trademark search or clearance exists. The rejected first icon (princess with side buns) shows how easily the association re-enters. Final store name: "Leia: Read Aloud" (operator decision 2026-10-14, after a first submission briefly carried "Leia Reads"; the AMO listing was renamed in the dev hub and 0.1.2 shipped the manifest rename).
- No public homepage, support URL, or hosted privacy policy exists yet (`copy/copy.json` `_url_note`). Host `privacy-policy.md` first; CWS and Edge both require a policy URL because reading page text is disclosed. The policy's contact section points at the store listing, so it needs one of these to exist.
- Publisher accounts: CWS ($5 one-time fee, new publishers can list two items), AMO (free), Edge Partner Center (free).
- No promo video; every store accepts its absence.
- The AMO review will likely ask about the esbuild-minified bundle; the review notes in `copy/firefox.md` pre-answer it and the source archive step is in that runbook.
- `store/screenshots/qa/` holds captures kept on purpose but not for upload: the internal CLI fixture article and an options-page frame that reads developer-facing.
